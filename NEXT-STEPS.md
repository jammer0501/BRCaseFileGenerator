## Relationship layer (done)

`generateCase()` produces independent random elements; the relationship layer annotates a
generated case with a solution — culprit, location roles, clue trail — without changing anything
in the case itself. Full causal/airtight mystery generation was ruled out as out of scope.

### UX

- **Generate Case** renders the case text and also generates a solution straight away, placed in
  a collapsed `<details>` panel ("Reveal Solution") below the case, so a GM can hand the case
  over without spoiling it.
- **Re-roll Solution** (inside the panel) generates a fresh culprit, location roles and clue
  trail for the *same* case. The case text is never touched.
- The solution is rendered as structured HTML blocks (Culprit / Locations / Clue Trail) by
  `renderSolution()` in `app.js`, not as appended plain text. This replaced the earlier
  "Generate Relationships" button that appended text to `#case-output`.

### Code

- `js/relationships.js`:
  - `generateRelationships(case)` → `{ culprit: { npcIndex, motive }, locationRoles: [{ locationIndex, role }], clueLinks: [{ clueIndex, foundAt, pointsTo }] }`
  - `describeRelationships(case, rel)` → display-ready strings, used by the page.
  - `formatRelationships(case, rel)` → plain-text version (kept for tests / future copy-to-clipboard).
  - Motive table (`MOTIVES`) lives inline.
- `app.js` keeps `currentCase` in memory so the solution can be re-rolled.
- Styles: `.solution*`, `.clue-*`, `.reroll-btn` in `styles/base.css` + `styles/blade-runner.css`.

### Rules

1. **Culprit** — one random case NPC plus a motive. Not theme-biased yet.
2. **Location roles** — the 3 case locations are shuffled into Crime Scene, Culprit's Haunt and
   Confrontation Site. No new locations are generated.
3. **Clue trail** — each clue gets `foundAt` (a case location or a case NPC, possibly the
   culprit — a "smoking gun" beat) and `pointsTo` (the culprit or a location).
   - **Witness clues** are always `foundAt` a location; they keep their own independently
     generated bystander NPC (deliberately not rewired to case NPCs, to stay non-destructive).
   - **Forward-only trail:** Crime Scene → Culprit's Haunt → Confrontation Site. A clue only
     points to a location later in the chain than where it was found — never to its own
     location, never back to the Crime Scene. Clues found on an NPC can point to any location
     after the Crime Scene.
   - Roughly 1 in 3 freely-rolled clues implicate the culprit directly; a clue found at the end
     of the chain always does.
   - **Guaranteed complete chain:** three distinct clues are reserved so every trail has
     something leading to the Haunt (found at the Crime Scene), something leading to the
     Confrontation Site (found earlier in the chain), and something implicating the culprit.

4. **Assignment hints** — assignments in `js/tables/assignments.js` are objects (`{ text, crimeScene?,
   culprit?, redHerring? }`) so the case and solution can't contradict the assignment text:
   - `crimeScene`: `generateCase()` makes sure one location matches it; the solution always
     uses that location as the Crime Scene. Places not in the tables map to the nearest one
     (five-star restaurant → Razdora Eatery, Sea Wall construction site → Sea Wall Docks).
   - `culprit`: `generateCase()` makes sure at least one NPC matches it (by type or occupation);
     the solution only picks a culprit from the matching NPCs.
   - `redHerring`: the assignment names an obvious suspect. The solution names the suspect NPC
     and states a verdict: framed (2 in 3, the `alternative` party did it) or genuinely guilty.
   - Replicant status isn't tracked; if the assignment says the culprit is a Replicant, the
     GM treats the chosen NPC as one.

Tests in `test/relationships.test.js` cover all of the above; `test/assignments.test.js` checks
every hint can be produced by the tables.

## Neon Requiem toolkit

Source: `THE_COMPLETE_TEARS_IN_THE_RAIN_TOOLKIT.pdf` — a 100-table d20 cyberpunk/Blade-Runner
sourcebook ("Neon Requiem"), in 5 parts: City, Synthetic, Hunter, Hunt, Rain. Tables cross-link
via `→` references and are designed to be rolled standalone.

**The standalone toolkit is its own app now**: the "digital sourcebook" roller (all 100 tables,
cross-reference chaining, quick recipes) lives in a separate, private repo, `NeonRequiemToolkit`
(locally `C:\dev\repos\NeonRequiemToolkit`). It was split out of this repo's gitignored `local/`
folder, which has been removed.

**Keep the table text out of this repo** — it's public and deployed via GitHub Pages. Don't
commit, push or deploy any of it from here. `/local/` stays gitignored as a guard.
